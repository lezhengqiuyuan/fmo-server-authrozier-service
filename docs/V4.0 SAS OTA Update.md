# V4.0 SAS OTA Update

## 1. 概述

SAS 启动时自动检查远端最新版本；实际升级由官方安装脚本 `install.sh --upgrade` 完成：

| 部署环境 | 更新方式 |
|----------|----------|
| 裸机（Linux / macOS） | `sas --update` 打印命令，或 `sas --update --yes` 执行官方升级脚本 |
| Windows | `sas --update` 打印最新发布页，手动替换 `sas.exe` |
| Docker | 日志提示 `docker pull` 命令，由外部工具更新 |

升级只覆盖程序目录（`sas` 与 `builtin/`），**不会改写配置文件或数据目录**。

版本检查为异步非阻塞，网络异常静默跳过，不影响正常启动。

---

## 2. 版本号

| 项 | 说明 |
|----|------|
| 格式 | semver `major.minor.patch`，如 `1.2.2` |
| 定义位置 | `src/Sas.csproj` → `<Version>1.2.2</Version>` |
| 运行时读取 | `AssemblyInformationalVersionAttribute`（自动剥离 `+sha`） |
| 比较方式 | `System.Version` 标准比较 |
| 命令行查询 | `sas --version` 输出纯版本号，供升级脚本比较 |

| 字段 | 类型 | 必需 | 说明 |
|------|------|------|------|
| `version` | string | 是 | 最新 semver 版本号 |

### 3.1 本地配置

```json
{
  "update": { "enabled": true }
}
```

| 字段 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `update.enabled` | bool | `true` | 是否在启动时检查远端版本 |

旧配置文件中若不存在 `update` 节，默认视为启用。

## 4. 启动时版本检查

```
SAS 启动
  ├─ 读取本地版本号
  ├─ 日志输出版本
  ├─ HTTP 监听器启动
  └─ config.update.enabled == true
       └─ 异步请求 sas.json（5 秒超时，不阻塞）
            ├─ 成功 → 解析 JSON
            │    ├─ 本地 < 远端
            │    │    ├─ 裸机 → [Warn] 新版本 + 升级命令
            │    │    └─ Docker → [Warn] 新版本 + docker pull 提示
            │    └─ 本地 >= 远端 → "Already up to date."
            └─ 失败 → 静默（网络不通 / 超时 / JSON 格式错误）
```

### 4.1 环境检测

| 检测条件 | 判定环境 |
|----------|----------|
| `Environment.GetEnvironmentVariable("DOTNET_RUNNING_IN_CONTAINER") == "true"` | Docker |
| `File.Exists("/.dockerenv")` | Docker |
| 其他 | 裸机 |

### 4.2 日志输出

**裸机环境，有新版本：**

```
[Warn] ┌─────────────────────────────────────────────────────────────────────────────
[Warn] │  New SAS version available: 1.2.2
[Warn] │  https://github.com/BG5ESN/fmo-server-authrozier-service
[Warn] │  更新说明：Bug fixes and performance improvements.
[Warn] │  Upgrade: curl -fsSL https://bg5esn.com/share/fmo/sas-installer/install.sh -o /tmp/install.sh && sudo bash /tmp/install.sh --upgrade
[Warn] └─────────────────────────────────────────────────────────────────────────────
```

**Docker 环境，有新版本：**

```
[Warn] │  Update: docker pull fmo/sas:latest && docker compose up -d
```

> **关闭版本检查**：在 `config.json` 中设置 `"update": { "enabled": false }`。

## 5. `sas --update` 命令

### 5.1 裸机（Linux / macOS）

```
sas --update
```

1. 请求 `sas.json` 获取远端版本
2. 输出当前版本、远端版本与官方升级命令
3. 退出，不修改任何文件

```
sas --update --yes
```

在打印命令后，下载 `install.sh` 到临时文件并执行：

```
bash /tmp/sas-install.sh --upgrade --yes
```

非 root 用户会尝试 `sudo bash ...`。升级脚本自身完成停服、覆盖、重启与健康检查。

### 5.2 Windows

```
sas --update
```

输出当前版本与最新发布页，由用户下载 zip 后替换 `sas.exe`。Windows 不执行 shell 升级脚本。

### 5.3 Docker

```
sas --update
```

```
Running in Docker. Update with:
  docker pull fmo/sas:latest && docker compose up -d
```

Docker 环境不执行自更新。

## 6. 官方升级脚本

URL：`https://bg5esn.com/share/fmo/sas-installer/install.sh`

### 6.1 入口

```bash
# 自动判断：已安装 → 升级；未安装 → 安装向导
curl -fsSL https://bg5esn.com/share/fmo/sas-installer/install.sh -o /tmp/install.sh && sudo bash /tmp/install.sh

# 显式升级（推荐用于自动化）
curl -fsSL https://bg5esn.com/share/fmo/sas-installer/install.sh -o /tmp/install.sh && sudo bash /tmp/install.sh --upgrade --yes

# 同版本强制覆盖
curl -fsSL https://bg5esn.com/share/fmo/sas-installer/install.sh -o /tmp/install.sh && sudo bash /tmp/install.sh --upgrade --yes --force

# 强制重装（进入配置向导）
curl -fsSL https://bg5esn.com/share/fmo/sas-installer/install.sh -o /tmp/install.sh && sudo bash /tmp/install.sh --install
```

| 参数 | 说明 |
|------|------|
| `--upgrade` | 强制升级，要求已安装 |
| `--install` | 强制安装 / 重装，进入配置向导 |
| `-y`, `--yes` | 自动确认，无交互 |
| `--force` | 目标版本不高于当前版本时也覆盖 |
| `-h`, `--help` | 显示帮助 |

### 6.2 升级流程

```
install.sh --upgrade
├─ root / 依赖校验
├─ 检测 $INSTALL_DIR/sas 与 config.json
├─ 读取当前版本：$INSTALL_DIR/sas --version
├─ 请求 sas.json，比较版本
│    └─ 已是最新且无 --force → 退出
├─ 确认（--yes 时跳过）
├─ 下载 tar.gz 到 mktemp 目录并解压
├─ 备份当前 sas 与 builtin/ 到 $INSTALL_DIR/.backup-<时间戳>
├─ 停止服务（systemd / launchd），pkill 残留进程
├─ 原子替换 sas，重建 builtin/
├─ 校正服务文件（存在则保留，缺失则补建）
├─ 启动服务并轮询 30 × 2s
│    └─ 失败 → 恢复备份 → 重启 → 输出最近日志 → exit 1
└─ 输出新版本、配置路径、数据路径、备份路径
```

### 6.3 目录布局

| 用途 | Linux | macOS |
|------|-------|-------|
| 程序 | `/opt/fmo-sas` | `/usr/local/opt/fmo-sas` |
| 配置 | `/etc/fmo-sas/config.json` | `/usr/local/etc/fmo-sas/config.json` |
| 数据（roots/roles/crl/archive） | `/root/.sas/` | `/var/root/.sas/` |

数据目录统一使用运行用户的 `~/.sas`：root 运行时 Linux 为 `/root/.sas`，macOS 为 `/var/root/.sas`；普通用户手动运行时为 `$HOME/.sas`。

新装时脚本通过 `--roots-dir` / `--archive-dir` 显式指定数据目录。升级只覆盖程序目录（`sas` 与 `builtin/`），不会迁移数据，也不会修改现有配置。卸载脚本会保留 `~/.sas`，需要彻底删除时手动执行 `rm -rf`。

安装或升级时，如果 `~/.sas/config.json` 与系统配置同时存在，脚本会提示该文件不会生效，避免误以为数据目录里的配置正在使用。

程序自身的默认配置解析顺序为：`--config` → `SAS_CONFIG` 环境变量 → 标准安装目录下的系统配置（仅当文件存在）→ `~/.sas/config.json`。

### 6.4 旧部署升级 / Legacy Deployment Upgrades

`install.sh --upgrade` 只识别以下条件：

```
/opt/fmo-sas/sas 存在（小写）
/etc/fmo-sas/config.json 存在
```

不满足时脚本会判定为未安装，退回安装流程。先确认部署类型：

```bash
# Linux：查看 systemd unit 的 ExecStart / WorkingDirectory
systemctl cat fmo-sas | grep -E 'ExecStart|WorkingDirectory'

# 查看安装目录与二进制文件名（注意大小写）
ls -l /opt/fmo-sas/sas /opt/fmo-sas/Sas /opt/emqx/fmo-sas/sas 2>/dev/null
```

| 部署方式 | 判断依据 | 不能直接 `--upgrade` 的原因 | 处理方式 |
|----------|----------|------------------------------|----------|
| 官方脚本安装 | `/opt/fmo-sas/sas` + `/etc/fmo-sas/config.json` | — | 见下方命令 |
| v1.0.5 之前的官方安装 | `/opt/fmo-sas/Sas`（大写），无小写 `sas` | 脚本检测小写 `sas`，Linux 文件系统区分大小写 | 见下方命令 |
| 手动安装 | 二进制不在 `/opt/fmo-sas`，或 `ExecStart` 指向其他路径，或通过 screen/nohup 启动 | 程序与配置均不在标准路径 | 见下方命令 |
| `fmo-emqx` 一体化部署 | `/opt/emqx/fmo-sas/sas`，配置 `/root/.sas/config.json` | 安装路径、systemd unit 与配置位置由 fmo-emqx 管理 | 见下方命令 |
| Docker / Compose | `docker ps` 中存在 `fmo-sas` 容器 | 容器内替换二进制不会持久化 | 见下方命令 |

完整命令：

```bash
# 官方脚本安装：升级
curl -fsSL https://bg5esn.com/share/fmo/sas-installer/install.sh -o /tmp/install.sh && sudo bash /tmp/install.sh --upgrade

# v1.0.5 之前的官方安装：覆盖安装（配置步骤选择 [3]）
curl -fsSL https://bg5esn.com/share/fmo/sas-installer/install.sh -o /tmp/install.sh && sudo bash /tmp/install.sh --install
```

手动安装迁移示例（完整命令）：

```bash
# 停止 screen / nohup 启动的旧进程
sudo pkill -f '/fmo-sas/sas'

# 如果旧部署由自定义 systemd unit 管理，先查询并停止
systemctl list-units --type=service | grep -i sas
sudo systemctl stop <上一步查到的服务名>

# 迁移原配置
sudo mkdir -p /etc/fmo-sas
sudo cp ~/.sas/config.json /etc/fmo-sas/config.json

# 下载并执行安装，配置步骤选择 [3]
curl -fsSL https://bg5esn.com/share/fmo/sas-installer/install.sh -o /tmp/install.sh && sudo bash /tmp/install.sh --install
```

`fmo-emqx` 一体化部署：

```bash
# 进入当初解压 fmo-emqx 安装包的目录（按实际路径修改）
cd ~/fmo-emqx
sudo ./install.sh --update
```

Docker / Compose：

```bash
# fmo-emqx docker 版
cd ~/fmo-emqx
sudo ./install.sh --update

# compose 版
docker compose -f /opt/emqx/docker-compose.yaml build --no-cache fmo-sas
docker compose -f /opt/emqx/docker-compose.yaml up -d --no-deps fmo-sas
```

`--install` 会重写 systemd / launchd 服务文件，使其指向新安装的 `sas`；已有配置和数据不会被删除。`<上一步查到的服务名>` 需替换为 `systemctl list-units` 输出中的实际服务名。

旧版本的 `sas --update` 行为：

| 版本 | 行为 | 风险 |
|------|------|------|
| 1.2.0 之前 | 自替换：下载对应 RID 的包，覆盖 `Environment.ProcessPath`，进程退出 | 不重启 systemd/launchd，服务不会自动拉起；若旧文件名为 `Sas`，替换后仍为 `Sas` |
| 1.2.0 起 | 只请求 `sas.json`、比较版本、打印官方升级命令 | 不修改任何文件，必须执行打印出的 `install.sh --upgrade` |

> 升级前建议备份配置：`sudo cp /etc/fmo-sas/config.json /etc/fmo-sas/config.json.bak`。升级只覆盖二进制与 `builtin/`，不会修改 `config.json` 和 `~/.sas`；启动失败会从 `.backup-<时间戳>` 自动回滚。

## 7. 错误处理

| 阶段 | 失败原因 | 行为 |
|------|----------|------|
| 请求 sas.json | 网络不通 / 超时 | 启动检查静默；`--update` 提示后继续打印命令 |
| `--update` | 无法解析版本 | 提示后继续打印升级命令 |
| 升级脚本：检测 | 未安装 / 缺少配置 | 报错退出，提示安装命令 |
| 升级脚本：下载 | HTTP 4xx/5xx / 超时 | 报错退出，旧版本继续运行 |
| 升级脚本：解压 | 包损坏 / 缺少 `sas` | 报错退出，旧版本继续运行 |
| 升级脚本：启动 | 新版本无法启动 | 自动回滚并重启旧版本，输出日志 |
| 新版本运行 | 配置不兼容 / crash | 外部 supervisor（systemd / launchd）继续拉起；可手动使用备份目录回滚 |

**备份策略**：升级前保留一份 `$INSTALL_DIR/.backup-<时间戳>`（二进制 + `builtin/`），仅保留最近一份。

## 8. 安全考量

1. **HTTPS only**：`sas.json`、assets 与升级脚本均通过 HTTPS 获取；`curl` 使用 `--proto '=https' --proto-redir '=https'`。
2. **SHA-256 校验**：升级脚本要求清单提供 `<rid>_sha256`，下载安装包后校验；缺失或不匹配立即中止。签名清单（Ed25519/Minisign）仍建议作为后续增强。
3. **显式触发**：启动时只检查版本，不静默替换；升级必须通过 `--upgrade` 或 `--update --yes` 触发。
4. **配置保护**：升级分支不调用配置向导，不修改 `config.json`，不删除数据目录。
5. **服务保护**：只覆盖程序文件；已有 systemd / launchd 服务文件默认不覆盖。
6. **可回滚**：启动健康检查失败时自动恢复升级前的二进制与 `builtin/`。
